# HVAC Sensor Validation & Metrology

A reproducible engineering case study for characterization, calibration, independent validation, dynamic-response analysis, stability assessment, measurement-uncertainty evaluation, and compliance-oriented interpretation of an HVAC relative-humidity sensor.

This repository is intentionally structured as an **analyst-side sensor-metrology workspace**. Python is used as the analytical tool; the engineering subject is measurement, calibration, validation, and evidence-based sensor performance assessment.

## Engineering Objective

The project asks a sequence of progressively stronger engineering questions:

1. **Can the measurement evidence be trusted?**
2. **What does the qualified evidence reveal about DUT measurement performance?**
3. **Can systematic error be modeled and corrected?**
4. **Does the frozen calibration generalize to independent validation data?**
5. **How does the sensor behave dynamically and over time?**
6. **What uncertainty is associated with the reported measurement result?**
7. **What engineering decision is justified by the evidence and stated requirements?**

The intended end-to-end workflow is:

```text
Dataset Qualification
        ->
Static Characterization
        ->
Repeatability / Reproducibility
        ->
Calibration Model Development
        ->
Independent Validation
        ->
Dynamic Characterization
        ->
Stability / Drift
        ->
Measurement Uncertainty
        ->
Final Engineering Assessment
```

## Analytical Boundary

This repository does **not** use hidden simulator truth.

Excluded information includes:

- private DUT personality/configuration
- hidden injected error components
- latent simulator states
- exact hidden bias, drift, or dynamic parameters
- other simulator-only truth unavailable to a real analyst

A core metrology principle throughout the project is:

```text
RH_Reference != exact physical truth
```

The reference instrument is itself a measurement system with finite uncertainty.

## Core Engineering Principles

### Measurement error convention

```text
Error = RH_DUT - RH_Reference
```

A positive value means the DUT reads high relative to the reference.

### Calibration / validation separation

Calibration observations and validation observations remain strictly separated. Validation data are not used to tune or refit the calibration model after model freeze.

### Evidence before conclusions

No accuracy, calibration, dynamic-response, drift, uncertainty, or compliance conclusion is made before the relevant evidence has passed its required technical gate.

### Measurement evidence, not simulator truth

Engineering conclusions are based on analyst-visible measurements, stated requirements, and uncertainty - the same class of evidence available in a real validation workflow.
